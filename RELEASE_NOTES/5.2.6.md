## Summary

This release adds a version 2 of the learner-path API that reads and writes learner paths through the CB extension service, and whitelists that new route so it passes API access checks. It also corrects the UPSMF profession/designation value from `ANM-UP` to `ANM_UP` and includes minor lint cleanup.

## ✨ Features

- **Learner path** — Added the learner-path v2 API: a protected `/learnerPathV2` route (GET + POST) that proxies to the CB extension service via `SB_EXT_API_BASE_2` (`34d28c9`).

## 🐛 Fixes

- **Learner path** — Whitelisted the `/protected/v8/learnerPathV2` route (added to both the whitelist map and the flat list) so it clears API whitelisting (`ea332ec`).
- **UPSMF** — Corrected the profession/designation value from `ANM-UP` to `ANM_UP` (`a2a7262`).

## ⚠️ Deploy notes & risk

- **New protected route depends on `SB_EXT_API_BASE_2`:** `/learnerPathV2` proxies to `${SB_EXT_API_BASE_2}/learnerpath` (CB extension service). Ensure `SB_EXT_API_BASE_2` is set in production and that the extension service actually exposes `/learnerpath`, otherwise the endpoint returns a forwarded 404.
- **Whitelist must ship with the build:** the new `/learnerPathV2` whitelist entry lives in `src/utils/whitelistApis.ts`; if `PORTAL_API_WHITELIST_CHECK=true` and the deployed build is stale, the route is blocked (403).
- **UPSMF value change:** any downstream consumer keyed on the old `ANM-UP` string must be updated to `ANM_UP`.
