## Summary

This is the first release of the proxy for the **Sunbird Spark** platform, which became production on 9 October 2026. It records everything that was changed to make Sphere, Ekshamata and the content portal work on Spark — sign-in and password reset, enrolment, certificates, course search and content upload — and adds two new things: certificates can now be checked by scanning their QR code, and participants of an event are emailed their certificate.

It is a major version because this code is built for the Spark backend and is not meant to run against the old production platform any more.

Production today runs an earlier build of this work (`72ed778`). Deploying this release also brings back **AI Studio**, which the new production has been running without since go-live, and unblocks the org status update in the org portal.

## ✨ Features

- **Certificate verification by QR code** — a scanned certificate is checked against the signed credential in Sunbird RC, and the course name comes from the credential itself rather than from what the caller sent (`f85d987`, `2274d42`).
- **Event certificates by email** — each event participant is emailed their certificate, and the participants list shows the email and when it was sent (`4ec1921`, `3762c38`).
- **Admin user search and update without a user session** — routes for back-office tools, authenticated with the platform API key (`cdc23cc`).
- **Mobile app on Spark** — user read and user search responses are adapted back to the shape the mobile app already expects (`36984bd`), and the course hierarchy response likewise (`e11cf4c`, `b37fd4c`, `fac024a`).
- **Content search** — field selection and paging (offset) handled for Spark search (`6d36cc7`, `e8f02d8`); ratings search reads through the common service (`79308f8`, `bd7299b`, `fb7a8b7`, `10807da`).

## 🐛 Fixes

**Sign-in, sign-up and profile**
- **Password reset by phone** — the reset now resolves the user from the identifier they entered, not from a `userId` field the request never carried (`212a180`).
- **Profile and TnC saves no longer fail when telemetry is down** — the telemetry call and the audit write are now side effects; only the actual profile update decides the response (`a58f0ff`).
- **Registration profile update** goes to the private lern endpoint and uses the right user id; profile and migrate calls use `userDetails.id` (`46b65c8`, `0d58ca9`).
- **Profile update on Kong** sends the user token header lern requires (`116c7fe`; added in `b5a21ee`, briefly reverted in `632c085`).
- **Accounts created without a usable password are now logged** — lern can report success while failing to create the Keycloak credential; that is now visible in the logs instead of silent (`8ada6ce`).
- **SSO login failures log Keycloak's actual reason**, so a wrong client and a wrong password can be told apart (`560051d`); the SSO client id moves to the `APP_SSO_CLIENT_ID` setting (`5702cf4`, `ef5b5d2`).

**Courses, enrolment and assessments**
- **Published courses can be enrolled in** — `batch/create` is forwarded to lern instead of being answered with an empty success; the old behaviour is still available with `STUB_BATCH_CREATE=true` (`98f9bab`). See the deploy notes.
- **Assessments no longer hang** when a question file is missing — the request now fails fast with a real status instead of never answering (`80aaafd`).
- **Course search** keeps competency-mapped courses, excludes only self-assessments, expands only the competencies that match the query, looks competencies up in the FRAC entity service, and stops asking for facets Spark rejects (`2c38643`, `f170a9e`, `78e9bc5`, `173626f`, `7407f55`).
- **Learner path** reads from cb-ext; the duplicate `learnerPathV2` route is removed (`1b3deb9`).

**Certificates and uploads**
- **Certificate download** works for both raw SVG and data-URI certificates and downloads as PNG (`72ed778`).
- **Uploads go to the asset upload API**, which certificate template images need on Spark (`9fd3eee`).
- **CDN URL rewriting** touches only the configured S3 domain (`c077dce`).

**Events, discussions and access**
- **Events dashboard: a security fix.** `GET /events` returned every user's events to anyone signed in, and an event's creator was taken from the request body, so it could be spoofed or hidden from its own creator. The creator now comes from the session, reads return only the caller's own events, and the dashboard no longer scans whole tables (`c83fa39`, `b3aa514`).
- **Errors from the mobile app's Kong proxy keep their real status** — a `401` from upstream was being reported as a `500` (`6c78bd9`).
- **Discussion forum** user lookup route whitelisted (`f7bbf84`); **org status update** endpoint whitelisted (`10e489a`).
- **Notifications and user lookups** use the public v1 endpoints and `notification/v2/send` instead of private paths Spark does not expose (`bfa9d56`, `ed9c501`).

## ⚠️ Deploy notes & risk

- **Never deploy this release to the old production cluster** (`aastar-prod-eks`, namespace `dev`). It is built for Spark: it calls `lern-service`, `knowlg` and other Spark services that do not exist there.
- **Rollback is NOT `release-5.2.16`.** That branch predates the Spark work and does not run on the Spark platform. On the current production, roll back to the image it runs today: `aastardev1/ui-proxies:upgrade_72ed778_1361`.
- **AI Studio needs a setting, not just this build.** `AI_STUDIO_API_BASE` is unset on the Spark production, so it falls back to `http://kong:8000/ai-studio`, and Kong there has no such route. Set `AI_STUDIO_API_BASE` to the AI Studio service, or add the route. Without it, every other part of this release works but the AI Studio screens fail.
- **Certificate verification reads Sunbird RC directly.** New setting `SUNBIRD_RC_REGISTRY_BASE`, defaulting to `http://registry-service:8081/api/v1`. Confirm that is the RC service name on production.
- **Check batch creation after publishing.** On Spark the publish job (1.0.2.2) now creates a batch when a course is published, and this proxy also forwards the portal's own `batch/create` (already live since go-live). Publish a course and confirm it ends up with exactly **one** batch. If it gets two, set `STUB_BATCH_CREATE=true` in `ui-proxies-config`, which leaves batch creation to the publish job as Sunbird designed it.
- **Events dashboard:** the faster events read wants the index `rc_events_createdby_idx` on `sunbird.rc_events (createdby)`. Without it the dashboard still works and falls back to a scan, logging that it did.
- **`learnerPathV2` is removed.** Any client still calling `/apis/protected/v8/learnerpathV2` gets blocked; use `learnerpath`.
- **Persist the image tag in the installer.** Installer runs on the Spark cluster have already silently reverted live changes once; an unpinned image here would be reverted the same way.

## Release & rollback

- **Deploy source:** `release-6.0.0`, cut from `production` at the release commit and tagged `v6.0.0`. Jenkins targets the branch, not the tag.
- **Rollback:** on the Spark production, set the `ui-proxies` image back to `upgrade_72ed778_1361`. Do not roll back to `release-5.2.16` (see deploy notes).
