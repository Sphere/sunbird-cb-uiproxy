## Summary

Fixes creator attribution on the AI Studio proxy added in v5.2.15. The proxy was sending the user's display name in `x-aastrika-creator`, and the AI service trusts that header over anything in the request body — so every video and quiz was recorded against a name rather than a user id. Two things broke as a result: people sharing a name became one row in the usage report, and "Your assessments" / "Your videos" came back empty, because that history is filtered by user id and no row carried one.

The id now travels as the creator, with the display name beside it in its own header.

## ✨ Features

_None — patch release._

## 🐛 Fixes

- **AI Studio creator attribution** — `x-aastrika-creator` carried the Keycloak display name, so `creator_id` was stored as, for example, `Prince Kumar Gupta` rather than the user id. `resolveCreatorId()` now resolves `session.userId`, falling back to the token's `sub`, and never a name or `userName`. The readable name moves to `x-aastrika-creator-name` via `resolveCreatorName()` — a header the AI service already reads, so **no change is needed on the service side** (`edf8053`).
- **A non-ASCII display name no longer fails the call.** Node rejects non-ASCII header values, so a name in Devanagari made the upstream request throw — surfacing as an opaque `500` from inside the proxy. The name header is now omitted when it is not ASCII-safe, and the service falls back to the name in the request body, which carries any script.

## ⚠️ Deploy notes & risk

- **Low risk, one function's worth of behaviour.** Two outgoing headers change. No route, no response shape, no dependency, no schema.
- **Both values are still derived from the session** and overwrite anything the caller sent, so attribution cannot be spoofed — unchanged from v5.2.15.
- **Content created under v5.2.15 keeps its old attribution.** Rows written while the name was the creator still carry a name in `creator_id`; this release does not migrate them. Expect the usage report to show a mix until the old rows age out, or until someone backfills them. Anything created after this deploys is attributed by id.
- **"Your assessments" and "Your videos" start working for new content immediately**, and will stay empty for anything created under v5.2.15, for the same reason.
- **No AI service change is required.** `x-aastrika-creator-name` is a header it already reads.
