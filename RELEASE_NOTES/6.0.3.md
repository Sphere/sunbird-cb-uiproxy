## Summary

Course search put courses nobody had edited at the top of the list, because it sorted by the last time anything about the course changed, including a new rating or a background system update. Search now sorts by when each course was last published, so the newest content comes first. This matches the learner portal, which now shows and sorts by the same date.

## 🐛 Fixes

- **Search sorted by the publish date** — `publicSearch` and `ratingsSearch` `/getCourses` sorted by `lastUpdatedOn`, which changes on every write to a course (ratings, metadata, system updates). The default sort is now `lastPublishedOn` when the client sends none, and the in-memory re-sort for competency searches (5+ competencies: level, then date) uses `lastPublishedOn`, falling back to `lastUpdatedOn` for a record without a publish date. A missing or unparseable date sorts last instead of breaking the order (`914aba5`).

## Verification performed

The search routes were read end to end: the client's `request.sort_by` is passed to the search service unchanged, while the top-level `sort` field the proxy also sends is not used by the search service.
