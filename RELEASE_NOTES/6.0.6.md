## Summary

The Bihar Staff Nurse registration form now asks whether the nurse works at the district level (a Sadar or Sub Divisional hospital) or the block level (a referral hospital, CHC, PHC or APHC). This release stores that answer, so reports can tell the two groups apart. It is saved on the user's profile straight away, and in the BNRC registration table as soon as DevOps adds one column.

## ✨ Features

- **Bihar Staff Nurse posting level** — `POST /public/v8/bnrcUserCreation` accepts `postingLevel` (`District` or `Block`; empty or missing is still accepted, so other Bihar forms are unaffected; any other value is rejected). It is saved on the user's profile in `professionalDetails.postingLevel` (empty for Student and Faculty registrations), and in `bnrc_registration_data_prod.posting_level` once that column exists (`03a4d96`).
- **Safe database write** — the route checks once whether the `posting_level` column exists and includes it only then (re-checking every 10 minutes while it is missing). Before the column is added, registrations are stored exactly as today; once it is added, the value starts being written with no redeploy (`03a4d96`).

## ⚠️ Deploy notes & risk

- **Pairs with learner portal (eagle-fusion) 5.1.8**, which adds the District/Block question and sends `postingLevel`. Deploy this first or together: on 6.0.5 a Staff Nurse registration from 5.1.8 is rejected with `"postingLevel" is not allowed`.
- **Database column (DevOps, on the database that holds `bnrc_registration_data_prod`):**

  ```sql
  ALTER TABLE bnrc_registration_data_prod ADD COLUMN IF NOT EXISTS posting_level TEXT;
  ```

  Optional for the deploy itself -- without it the value is kept on the profile only. Run it to get the value into the table and reports.
- **Never deploy to the old production cluster** (`aastar-prod-eks`, namespace `dev`); this build is for Spark.
- **Risk:** low. One optional field on the Bihar registration route; existing requests are unchanged.
