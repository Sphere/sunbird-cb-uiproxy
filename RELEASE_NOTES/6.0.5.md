## Summary

Bihar is launching registration for staff nurses, who sign up differently from CHOs. The learner portal now has a separate Staff Nurse form. Its facility list ends in "Others", so a nurse whose facility isn't listed can type it in. This release lets the registration service accept that choice and save it, the same way the Madhya Pradesh form already does.

## ✨ Features

- **Bihar Staff Nurse "Others" facility** — `POST /public/v8/bnrcUserCreation` accepts `facilityNameOthers` (only `'Others'`, empty or null). The typed facility name arrives in `facilityName` and is saved as before, in the profile and in `bnrc_registration_data_prod.facility_name`. `facilityNameOthers` is saved in the user's profile (`professionalDetails`), and is empty for Student and Faculty registrations. Before this, the field was rejected as unknown and the registration failed (`6a22f19`).

## ⚠️ Deploy notes & risk

- **Pairs with learner portal (eagle-fusion) 5.1.6**, which adds the Staff Nurse form at `/bnrc/register?service=StaffNurse`. Deploy this first or together. A Staff Nurse who picks "Others" fails to register until it is live; listed facilities work with or without it.
- **Existing Bihar forms are unchanged.** Student, Faculty, ANM, GNM and CHO requests never send `facilityNameOthers`, and the schema still rejects every other unknown field.
- **No database change.** `bnrc_registration_data_prod` has no `facility_name_others` column, so the database row only shows the typed name in `facility_name`. If reports need to separate "Others" entries, DevOps would add that column and this route would write it; not part of this release.
- **Never deploy to the old production cluster** (`aastar-prod-eks`, namespace `dev`); this build is for Spark.
- **Risk:** low. One optional field added to the Bihar registration route.
