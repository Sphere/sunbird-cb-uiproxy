## Summary

Onboards the Aastrika AI Studio service into the portal proxy. The AI service turns a document into a narrated training video and source material into validated MCQ quizzes; until now the portal had no route to it, so the UI could only reach it by calling the gateway directly. It is now available at `/protected/v8/aiStudio/*`, following the same shape as the existing playlist onboarding.

Numbered as a patch in the 5.2.x line, though it adds a feature surface rather than fixing a defect. That is a deliberate choice to keep the release train continuous; nothing about the change itself depends on the number. No existing route, handler or constant changes behaviour.

## ✨ Features

- **AI Studio proxy** — 22 routes across four areas, mounted at `/protected/v8/aiStudio` (`efd20a0`):
  - **Studio** — `upload`, `list-voices`, `generate-plan`, `revise-plan`, `generate-video`, `get-video`, `list-videos`, `download-video`, `delete-video`
  - **Quiz** — `languages`, `upload`, `generate`, `list`, read, `update`, `export`, `delete`
  - **Artifacts** — `upload`, read, `delete`
  - **Usage** — `get-report` over both POST and GET
- **Both path shapes are served.** Each area answers under `/aiStudio/<area>/…` and `/aiStudio/v1/<area>/…`, because a client written against the AI service's own API keeps its `/v1` and changes only the host. One router, two mounts, identical upstream target.
- **Creator identity is derived, not accepted.** The signed-in person travels to the AI service in `x-aastrika-creator`, resolved from the portal session and overwriting anything the caller sent, so spend cannot be recorded against another user. Resolution order is Keycloak display name → Sunbird `userName` → user id; with none of them the header is omitted and the service records `admin`.
- **A wildcard per area** carries an endpoint the AI service adds later, so a new upstream route is reachable through the portal without a change here.
- **One access log line per request** — method, path, upstream status, duration, creator, and whether the request took a named route or the wildcard.
- **Postman collection** for the UI team at `postman/aastrika-ai-studio-uiproxy.postman_collection.json`, plus `npm run dev:aiStudio` to exercise the routes without Cassandra or Keycloak.

## ⚠️ Deploy notes & risk

- **Low risk, additive.** Three existing files change, by four lines of executable code between them: two lines mounting the router, one new constant, and one constant rewritten to a hoisted `const` with the same resolved value. Everything else is new files.
- **`KONG_API_BASE` was rewritten** from an inline expression to a module-level constant so the new default can derive from it. Verified to resolve identically with the variable unset, set to `http://kong:8000`, and set to the stage host.
- **The whitelist grew by 25 entries, all prefixed `/protected/v8/aiStudio/`.** `URL_PATTERN` is scanned on every request to the portal and the first match wins, so this was checked rather than assumed: all **308** pre-existing routes were run through `validateAPI`'s exact resolution logic before and after, and none resolved differently.
- **The five `:rest+` wildcard entries are required, not stylistic.** The concrete entries cover only the portal path shape; the `/v1/…` shape the UI actually sends is allowed solely by the wildcard. Removing them returns `403` for every request the UI makes, before it reaches the router.
- **Small shared cost.** `URL_PATTERN` went from 297 to 322 entries and `validateAPI` recompiles every pattern per request, so all portal traffic does roughly 8% more work in that one loop. No behaviour change.
- **Long requests hold a worker.** Planning, quiz generation and media upload can run up to 200s, inside the app's existing 240s connect timeout. Observed in testing: `quiz/upload` 37.6s, `quiz/generate` 24.0s, `generate-plan` 18.9s. Heavy concurrent use consumes workers other routes could have used.
- **Kong must forward `x-aastrika-creator`.** Confirmed on the deployed route — sending `Priya Sharma` recorded `Priya Sharma`, unmodified. If a different Kong route strips unknown `x-` headers, content is recorded against `admin`; nothing else breaks.
- **`generate-video` is the only call that spends money.** Planning and revising are free. The UI should show `costEstimate.totalUsd` from `generate-plan` before offering the render.

## ✅ Pre-deploy checklist

- [ ] Lint, `tsc` and the test suite pass on the release commit.
- [ ] `GET /protected/v8/aiStudio/quiz/languages` returns `200` — this one call confirms the Kong route exists, strips its prefix, and is reachable.
- [ ] An unknown path under `/aiStudio` returns the **AI service's** `NOT_FOUND`, not Kong's "no Route matched" — confirming a prefix route, without which the wildcard buys nothing.
- [ ] After creating content, the usage report's Creator column shows the individual user, not `admin` and not the portal's Kong consumer name.
- [ ] A user can delete their own content, and **cannot** delete another user's.
- [ ] A finished video downloads in a real browser — the `302` points at storage, which must be reachable from outside the cluster.
- [ ] Rollback reference confirmed: previous release branch `release-5.2.14` / tag `v5.2.14`.

## Release & rollback

- **Deploy source:** `release-5.2.15`, cut from `production` at the release commit and tagged `v5.2.15`. Jenkins targets the branch, not the tag.
- **Rollback:** re-run the deploy pipeline against `release-5.2.14`. Clean — the feature is additive, so reverting only removes the `/aiStudio` routes. No data migration, no schema change, nothing else depends on it.

## Verification performed

- **62 automated cases** against a mock AI service, covering every route, the identity header, error relay, streaming, and both path shapes. Run 60 consecutive times with zero failures after a connection-reuse defect in the harness was fixed.
- **Full product flow exercised end to end** against the deployed Kong route at `https://sphere.aastrika.org/api/ai-studio`: document upload → plan → revise → render → poll → download, and source upload → quiz generation → correction → export as xlsx and csv. All statuses `200`/`201`/`202`. Content created during testing was deleted; usage totals were identical before and after.
- **`POST /v1/artifacts/upload` failed with `400 UPLOAD_FAILED` during testing.** Isolated to the AI service by reproducing it with the proxy out of the path, characterised (every input failed, including a request with no file, while `quiz/upload` and `studio/upload` wrote to storage normally), reported, and confirmed fixed upstream before release.
