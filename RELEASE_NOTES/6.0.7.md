## Summary

The Bihar Staff Nurse registration form now asks for the type of facility first (Sadar Hospital, Sub Divisional Hospital, Referral Hospital, CHC, PHC or APHC), then the district, block and facility. This release stores that facility type, the same way the MP and UPSMF forms already store theirs. It is saved on the user's profile straight away, and in the BNRC registration table as soon as DevOps adds one column.

## ✨ Features

- **Bihar Staff Nurse facility type** — `POST /public/v8/bnrcUserCreation` accepts `facilityType` (`SH`, `SDH`, `RH`, `CHC`, `PHC` or `APHC`; empty or missing is still accepted, so other Bihar forms are unaffected; any other value is rejected). It is saved on the user's profile in `professionalDetails.facilityType` (empty for Student and Faculty registrations), and in `bnrc_registration_data_prod.facility_type` once that column exists (`7949d91`).
- **Optional columns, one check** — the safe database write added for `posting_level` in 6.0.6 now covers `facility_type` too: the route checks which of the two columns exist and writes only those, re-checking every 10 minutes until both are present. Before a column is added, registrations are stored exactly as today; once it is added, the value starts being written with no redeploy (`7949d91`).

## ⚠️ Deploy notes & risk

- **Pairs with learner portal (eagle-fusion) 5.1.9**, which adds the facility-type question and sends `facilityType`. Deploy this first or together: on 6.0.6 a Staff Nurse registration from 5.1.9 is rejected with `"facilityType" is not allowed`. Learner portal 5.1.8 keeps working on 6.0.7.
- **Database column (DevOps, on `prod_data_reports`, the database that holds `bnrc_registration_data_prod`):**

  ```sql
  ALTER TABLE bnrc_registration_data_prod ADD COLUMN IF NOT EXISTS facility_type TEXT;
  ```

  Optional for the deploy itself -- without it the value is kept on the profile only. `posting_level` was added on 2026-11-17.
- **Never deploy to the old production cluster** (`aastar-prod-eks`, namespace `dev`); this build is for Spark.
- **Risk:** low. One optional field on the Bihar registration route; existing requests are unchanged.
