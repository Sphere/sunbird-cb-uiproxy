## Summary

Support staff could not download certificates from the self-service portal for some learners: Download failed with an error even though the certificate had been issued and verifies correctly. These learners have a second, leftover enrolment record for the same course from an old portal bug, and the proxy read that empty record instead of the real one. The proxy now reads the learner's real enrolment, so Download works, and it answers "No certificate has been issued" instead of an error when there is genuinely nothing to download.

## 🐛 Fixes

- **Certificate download picks the learner's real enrolment** — `GET /apis/public/v8/publicCertificateFlinkv2/download` (used by the self-service portal) read `rows[0].issued_certificates[0]`. When a leftover row (`active` null, no certificate) came back first, it threw and returned 500. It now picks the active row, then a completed one, then any row carrying a certificate, and returns 404 when none has one. The CQL now binds `userid`/`courseid` as parameters instead of pasting them into the query, and the route stops after a 400 (an invalid key used to send 400 and still carry on) (`6413dd4`).

## Verification performed
